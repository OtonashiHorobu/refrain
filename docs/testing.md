# Testing

## Unit tests

The test binary uses Boost.UT and contains every suite in one process:

```bash
build/Release/bin/refrain-tests
```

Pass a suite name or a test name to run a subset:

```bash
build/Release/bin/refrain-tests "world/rwf"
build/Release/bin/refrain-tests --help
```

CTest runs the same binary:

```bash
ctest --preset conan-release --output-on-failure
```

## Continuous integration

```bash
scripts/ci.sh --offline
```

The pipeline checks, in order: vendored recipes against the lock, the platform
abstraction boundary, a lockfile-pinned Conan install, a full configure and
build, the unit tests, schema generation drift, the C ABI headers as C11, the
command-line contract, the runtime replay smoke, archive extraction, the crash
reporter smoke and `clang-format` over first-party sources.

`--skip-configure` and `--skip-build` reuse an existing build directory.

## Fixtures

All fixtures under `test/fixtures/` are synthetic or generated by the
repository tooling. The tree contains no game jars, extracted assets, world
saves or logs. Golden files under `test/fixtures/golden/` capture command
output and canonical file encodings; regenerate them with the documented
command in `test/fixtures/golden/README.md` when a deliberate output change is
made.

## Determinism

Tests that cover the simulation compare the state hash across two runs, or
across an encode and a decode. A change that alters the hash must come with a
format or behavior change that explains it.

## Adding a suite

Create a file under the matching directory in `test/`, for example
`test/world/test_my_feature.cpp`, and define a `boost::ut::suite`. The CMake
build globs the directory, so no build file edit is needed. Prefer a negative
case over a second happy path.
